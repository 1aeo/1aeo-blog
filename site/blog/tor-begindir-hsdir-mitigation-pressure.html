Follow-up — Pressure after Tor 0.4.9.15

Version scope: Tor 0.4.9.15. Instrumented: October 30–November 5; stock: October 29–November 5, 2026, Coordinated Universal Time (UTC). Custom patch: metrics and hardening. HSDir: hidden-service directory.

Definitions#

A circuit is a Tor path carrying many streams (logical connections). A custom patch adds metrics that count streams closed while waiting for HTTP. Stock Tor’s tor_relay_congestion_control_total{state="cc_circuits",action="circs_closed"} counts closure marks only for circuits with congestion-control state.

HTTP-wait-dominated windows have at least 80% of classified streams closed while waiting for HTTP. HSDir GET-largest windows have GET requests as their largest classification, not necessarily a majority.

Relay labels are anonymized.

Takeaways#

1. Two high-rate directory-stream patterns were observed on Tor 0.4.9.15. Active HTTP-wait-dominated windows averaged about 50,000 admissions/s with few defense events: 208 HSDir request-limit refusals/s and 5 BEGIN_DIR rate-limit events/s. Active HSDir GET-largest windows averaged 1,583 HSDir request-limit refusals/s. The HSDir limit helps; substantial stream pressure remains.

2. Tor 0.4.9.15’s HSDir request limit did not prevent 100% main-thread CPU. Stock 0.4.9.15 Relay LF sustained about 56,000 additional admissions/s and 474 Mbit/s more read bandwidth than before the high-rate surge, for about 45 minutes.

3. Tor 0.4.9.15’s HSDir request limit refused half of HSDir GET requests across 206 HSDir GET-largest windows on 118 relays. Relay BP averaged 7,962 HSDir GET requests/s.

4. Later BEGIN_DIR cell positions within a circuit were more common in HTTP-wait-dominated windows. Positions 101+ held most cells in 111 HTTP-wait-dominated windows on 91 relays, versus no GET-largest window.

3. Tor 0.4.9.15’s HSDir request limit refused half of HSDir GET requests#

“One HSDir request per circuit” shares one allowance between GET and POST. The second request is refused before descriptor lookup and closes its circuit. GET plus POST refusals match its counter in 382 complete instrumented windows across 129 relays, October 30–November 5, 2026 (UTC). GET totals include refusals.

Methods#

October 30–November 5: the full pattern groups contain 355 of 385 selected instrumented windows and share 86 relays. Windows were selected when BEGIN_DIR stream/cell or individual defense-counter rates reached 500/s. All 9 windows overlapping November 5 were Other/mixed.

Rates divide combined counts or bytes by combined observation time; longer windows contribute more. CPU averages weight its own measured intervals. Timeline steps and peaks use roughly one-minute averages. Bandwidth covers all relay traffic. Public times use 15-minute rounding. Grey hatching marks unavailable measurements, not zero traffic or CPU use.

HTTP-wait closure classifications count a previously unclassified linked directory stream once, with empty input at cleanup or on a closing-stream/circuit path. They identify neither closure cause nor waiting duration. Effective BEGIN_DIR rate/lifetime settings were not verified throughout. These observations do not measure upgrade savings; the extended period also includes Tor’s November 4 report of directory load from older-client restart loops.
