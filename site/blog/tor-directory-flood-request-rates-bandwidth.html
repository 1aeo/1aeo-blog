Version scope: Tor 0.4.9.14 with our custom metrics patch. Tor 0.4.9.15, released October 28, adds directory-request DoS controls, including per-circuit BEGIN_DIR rate limiting and a hidden-service directory (HSDir) request limit. The measurements below describe 0.4.9.14, not the effect of those new controls.

Relay labels such as Relay BM are anonymized. A majority is more than half of classified directory streams; bandwidth covers all relay traffic.

HSDir GET requests: 10× the written bandwidth in Relay BM. Relay BM averaged 398 Mbit/s (megabits per second) written when HSDir GET requests were the majority, versus 38 Mbit/s when “Closed while waiting for an HTTP request” was the majority. Higher written bandwidth accompanied the HSDir GET stage in 44 qualifying periods on 37 relays; average observation span about 3 h, Relay BM about 2¾ h.

HSDir GET requests exceeded half of directory streams for at least 90% of measured time. This held in 32 periods on 27 relays, totaling about 102 observed relay-hours and averaging about 3¼ h per observation. Relay O averaged 1,542 HSDir GET requests/s and 609 Mbit/s written across about 2½ h.

HSDir GET request rates and written bandwidth in Relay Y fell, then rose together. Relay Y’s majority classification switched HSDir GET requests → “Closed while waiting for an HTTP request” → HSDir GET requests. GET rates averaged 1,542 → 344 → 1,523 requests/s; written bandwidth 494 → 149 → 515 Mbit/s, across about 2½ h. Written bandwidth rose again in 3 of 5 qualifying gap-free sequences on four relays; average span about 2¼ h.

Methods #

Categories. HSDir GET requests fetch onion-service descriptors; HSDir POST requests upload them. “Closed while waiting for an HTTP request” is our custom metric label for directory streams that close in Tor’s HTTP-request-wait state, with an empty input buffer and no earlier request classification. It does not identify the closure cause or prove that no bytes ever arrived. Unparsed directory streams is a custom fallback category. It includes invalid or unrecognized input and remaining unclassified streams counted at closure, such as partial buffered requests.

Rates and totals. Sampling is nominally every 60 seconds. Rates use original counts or bytes divided by measured seconds; averages use summed counts or bytes divided by summed measured seconds. BM’s peaks are the highest observed 60-second averages, not instantaneous peaks. Its combined peak adds read and written bytes within each interval before taking the maximum. Cumulative tables can include counts recovered across missing-rate intervals.

Display precision. Rates, gigabytes, percentages and ratios are rounded for display. Calculations and grouping use unrounded measurements. Positive values below one appear as <1; exact zeros remain 0. Inequalities preserve meaningful percentage boundaries.

Comparison groups. For rate comparisons, a category has a majority when it accounts for more than 50% of classified streams in a measured interval, using all nine categories. The 44 paired comparisons require at least 15 measured minutes in each majority state. The 32-period test requires an HSDir GET majority for at least 90% of time with supported rates; three qualifying periods have gaps. Ten relays occur in both groups in different observations. These are separate tests, not a partition of the dataset.

Three-stage sequences. The five gap-free cases were selected without using bandwidth: exactly three consecutive majority stages—HSDir GET requests, “Closed while waiting for an HTTP request,” then HSDir GET requests—with at least 15 measured minutes per stage. Written bandwidth in the final stage exceeded the middle stage in three cases and was lower in two. This small selected group does not estimate all reversals.

Missing data and time. Grey hatching means no supported rate measurement, not zero traffic. Main-thread saturation may delay MetricsPort; these observations do not establish each gap’s cause. Tor’s networking runs on its main thread. Missing rates stay blank; steps connect adjacent measured intervals only. Chart and comparison-table starts and durations are rounded to 15-minute blocks, with intervals mapped uniformly onto those bounds. The full-data appendix instead shows dates and durations rounded to half-hour blocks, with counts and traffic totals rounded for display. Average spans use original durations before rounding and include gaps. Spans need not describe complete attacks or continuous behavior.

Scope. Timeline and overlay header percentages and appendix groups use whole-period classified-stream counts, not time shares; Mixed means no category exceeds 50%. Whole-relay bandwidth includes all traffic and does not measure per-request wire cost or client delivery. Part 3’s internal response bytes use a different accounting layer and cohort. These observations establish associations, not causes.

Additional traffic data for Relay BM #

During Relay BM’s switch, written bandwidth fell 90% while read bandwidth rose 57% (35 → 54 Mbit/s). Read increased in 42 of the 44 comparison periods, on 35 relays. The traffic responsible for the read increase is unknown.

Relay BM’s average written bandwidth fell by 359 Mbit/s while read bandwidth rose by 20 Mbit/s. Combined read-plus-written bandwidth averaged 432 → 93 Mbit/s (−79%).
